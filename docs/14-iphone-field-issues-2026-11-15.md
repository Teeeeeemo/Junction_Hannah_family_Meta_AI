## 3. PHONE-01：预览缩放、裁切与点击

**现象与证据**

- 用户反馈 App 内“原生眼镜界面预览 · 模拟”区域可以双击放大，但按钮无法点击。
- 01:24 截图显示右侧细节点按钮文字被裁切，底部控件也贴近容器边界。
- 该截图已出现作品名 `Reproduction of the Mona Lisa`、细节点列表，以及 Pause、Next、倍率、Intro 等控件，说明预览已经渲染了导览内容。

**已核对事实**

- `MuseumPhoneView.swift` 以 `UIViewRepresentable` 直接承载 SDK 返回的 UIView，并设置固定 320 点高度。
- IPA 内 DAT 1.0.1 的预览页面使用 WebView，HTML viewport 指定 `width=600`；当前宿主没有显式处理该预览的用户缩放。
- 双击网页缩放与应用的 2×／4×作品局部窗是不同操作。
- `GlassesDisplay.swift` 已注册按钮回调，仍需验证实际触摸能否到达对应回调。

**尚未确认**

不能仅从裁切截图断言“坐标必然错位”或“回调一定失效”。需区分 WebView 缩放／嵌套滚动竞争、实际触摸未命中、点击回调未送达，以及选点成功后因失跟而无声音。

**复现与验收要求**

1. 在实际 iPhone 完成一次作品识别，显示原生预览。
2. 记录初始布局及双击前后的缩放；按钮应完整可见，预览缩放不应影响应用的艺术品倍率状态。
3. 点预览中的 `1×`，检查是否变为 `1.25×`；该操作可与定位门槛分开验证。
4. 点一个细节点，分别记录触摸位置、SDK click identifier、回调、已选编号和定位／播放状态。
5. 与下方手机控件交叉验证。手机按钮通过，不代表预览按钮通过。

修复方向：按设计画布等比例承载预览，处理预览内缩放与外层滚动的关系，核对触摸命中；使用实际屏幕点击回归，不能以直接调用业务函数或注入 click identifier 代替触摸验收。

## 4. PHONE-02：有文字，无实际语音

**现象**

用户反馈屏幕出现文字描述但没有声音。后续《蒙娜丽莎》截图已包含作品标题和细节点列表；语音状态、实际输出设备与音频播放计数未出现在截图内。

**当前实现与边界**

- 0.2.0 已有 `NativeLiveVoice.swift`、认证 WSS、PCM 播放和 `TourNarrator` 集成，不能沿用旧版“语音尚未开发”的结论。
- 识别／描述经 HTTP 返回，语音经独立 Gemini Live 会话返回；文字成功不证明音频已收到或播放。
- 已识别导览默认使用 Gemini Live；离线布局样例使用明确标记的系统朗读。
- 本轮仅验证公共测试入口的认证 WebSocket 握手成功，没有为此检查启动新的 Gemini 音频会话，也没有证实手机播放成功。
- 发布记录仍保留真实云端验收失败；离线 PCM 与 UI 检查不能代替手机实际声音验收。

**需收集的诊断信息**

语音来源、voiceStatus、当前点位、locationBlocked、是否 awaitingContinue、实际音频路由、收到的 PCM 字节与实际播放进度、红色错误。预览中的 Pause 文案只反映应用状态，不能单独当作扬声器已经发声的证据。

**验收要求**

分别验证总览、自动 1 号、手动改点、暂停后追问与继续。手机实际可听到声音；音频不足／连接失败时明确报错；进入定位等待时清楚说明暂停原因，不把静默状态显示成正常播放。

## 5. PHONE-03：二维作品失跟，细节框缺失

**截图确认**

《蒙娜丽莎》已出现在视频画面中，下面有作品和点位列表，但状态为 `Image tracking: lost`，未看到持续细节框。

**代码已知行为**

- 当前使用 Vision 作品包围框跟踪，再映射细节区域；这是基础二维框跟踪，不是完整透视跟踪或光学映射。
- 新跟踪结果或输入超过时效门槛会清除几何；输入间隔超过 1 秒时会关闭跟踪并要求重新扫描。
- 对在线导览，当前细节不可定位时会阻止或暂停依赖定位的细节讲解。
- 真正失跟后的持续自动重定位／再识别仍不完整。

截图无法确定本次失跟由相机断帧、Vision 置信不足、结果延迟、视角变化还是其他状态问题引起。不能仅靠截图归因为网络、曝光或用户移动。

**修复与验收方向**

保存实际画作录像，记录帧时间、跟踪耗时、置信度与状态转换；验证静止、缓慢移动、短遮挡和恢复。失跟应及时清框，恢复后重新确认同一作品／点位；不能通过关闭定位门槛，让声音配合错误位置继续播放。

## 6. PHONE-04：镜片现实框尚未实现

`MuseumPhoneView.swift` 有手机相机图像内的矩形 overlay；`GlassesDisplay.swift` 当前发送标题、点位、控制与局部图像，没有绘制对准现实作品的细节框，也没有完成相机到佩戴者视野的光学校准。

所以“手机视频里有基础框代码”“预览中已有作品列表”“Vision 合成图像测试通过”都不能被描述为用户 A 版现实持续跟随框已交付。修复需明确公开显示通路、几何／校准和更新时延，并保留实际佩戴验收。

## 7. PHONE-05：首次未识别后不持续发现新作品

**实测顺序**

01:18 截图中的镜头主要对着电脑键盘／触控板。状态说明未发现艺术展品，预览显示 `Aim at an artwork`。这一次拒绝生成作品导览符合当前画面；该段说明不是讲解卡片，也不是语音故障证据。

**已确认原因**

`GlassCameraModel.receive()` 仅在有后端、至少收到 8 帧且未尝试过时自动启动一次分析任务。任务内最多进行三次观察；返回无作品／不确定等结果后，不会因后来转向画作而持续自动重扫。`attemptedAutomaticScan` 已置为 true。

**当前绕行**

转向画作后手动点击“重新识别”。后端连接和当前帧均需可用。

**完成标准**

未找到作品时进入明确、可取消且有节流／退避的搜索状态；作品出现后自动尝试，避免每帧请求云端。锁定作品后不因背景变化频繁换目标；在 UI 上区分搜索、待确认、分析、导览、失跟和失败。

## 8. PHONE-06／07：预览与识别连接脱节，入口及服务版本问题

**本轮已确认**

- 用户确认曾“尚未连接后端”。Mock 手机相机模式可独立开始预览，因此有视频却不请求 Gemini。
- App 出帧后会收起连接设置；后端未连接时，这个行为容易掩盖必要的下一步。
- 手机后端连接使用内存中的会话信息，App 重启后没有自动恢复该连接的流程。
- 本机旧测试入口过期，实际返回 HTTP 410；旧运行进程的 `/api/artwork-candidates` 返回 404。

**本次运维修复结果**

已重新构建当前 Web 产物、重启匹配 0.2.0 的本机后端与测试入口，保留原 HTTPS 通道。新入口 200、带 cookie 的配置接口 200、未授权访问 401；作品搜索接口对空请求返回正确的 400 输入验证错误。认证 WSS 握手成功。

这些结果证明路由和入口可用，不证明 Gemini 完整推理、手机音频或框追踪已通过。本文件不保存入口 URL、访问码、cookie 或 API Key。

**剩余改进**

未连接后端时，明确显示“仅预览，尚未开始识别”，保持连接入口醒目；连接时检查必要接口／版本与有效期；处理断线、过期和重新鉴权。部署说明必须区分源码已拉取、后端进程已重启和手机 IPA 已安装。

## 9. PHONE-08：参考资料和页面说明不清晰

- “仅作视觉观察”仍可调用 Gemini 识别、生成观察性讲解和细节，不代表只预览或关闭语音；当前名称容易产生误解。
- “大都会博物馆”实际仅对应梵高《麦田与柏树》的一份已准备记录，不是全馆作品库。镜头前应为该作品或其复制图；其他画作使用“仅作视觉观察”。
- 选择参考资料不等于成功识别，也不替代当前画面的验证。
- 原生 Display 预览、未识别状态说明和真正的讲解卡片需要更明确地区分；未发现作品时应提示对准作品／重新尝试，而不是让用户在空预览中寻找语音开关。

建议明确标注“无馆方资料：仍识别并讲解可见内容”以及具体作品名，并解释未连接、未发现作品与无可靠历史出处的不同含义。不得为《蒙娜丽莎》等没有已准备来源的作品强行套用梵高资料。

## 10. 下轮验证顺序与未决信息

1. 真机独立验证预览倍率点击和细节点选中，不以是否发声作为唯一点击结果。
2. 对同一段二维画作录像记录失跟原因，修复重定位与讲解状态联动。
3. 在明确的音频路由上验证 Gemini 总览、自动首点、改选和追问／继续，保留收到与实际播放音频的证据。
4. 补足后端连接、过期入口、自动搜索和文案回归，再生成新的可追溯 IPA 进行手机验证。
5. 镜片现实跟随框单独实施和验收，不能用手机图像内框替代。

Gemini Key 的具体剩余额度／余额尚未查到：本机没有 Google 账单／用量读取授权。当前没有证据证明“无语音”由额度耗尽引起，不将其列为已确认根因。
