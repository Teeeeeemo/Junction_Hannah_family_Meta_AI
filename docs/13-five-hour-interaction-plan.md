# 核心交互收口计划：五小时模拟器交付

> 执行方式：集成负责人、功能开发、测试、独立验收四个角色协作。按现有 PRD 修复，不改变产品范围；有依赖的步骤串行执行。

**Goal:** 在用户给定的五小时窗口内，交付可重复测试的 iOS 模拟器主流程、构建及真机自验清单。

**Architecture:** 手机、原生 DAT HUD、语音共享导览状态；点位定位可靠后才播放对应讲解。模拟器与云服务的证据分别记录，现实对齐及实际眼镜输入输出由用户最后上机验收。

**Tech Stack:** Swift / SwiftUI、Meta DAT 1.0.1、Vision、AVAudioEngine、TypeScript / Gemini、XCUITest。

日期：2026-11-15，Europe/Helsinki。T+0 为用户确认“五小时、设备可用”的时刻；随后用户明确：本轮先做 iOS 模拟器测试，最后自行真机验收。以下是时间预算和完成门槛，不是所有功能已经完成的声明。

## 3. 每个可用版本立即回归并提交

用户补充要求：每次新增或完善一个版本，回归后可用就立即提交并推送 GitHub 开发分支，不等最后集中提交。

- 每个检查点保留与源码对应的测试记录，缺陷未过的版本不当作可用版本推送。
- 第一检查点是可重复运行的模拟器版本：基础逻辑／编译／完整离线 UI 通过，文档准确列出云端及现实框缺项。必须包含能独立编译的依赖文件，不能只提交依赖未提交类型的零散修复。
- 原生云端闭环通过后再形成下一检查点；后续功能同样执行“修改→相关回归→独立复核→提交→推送”。
- 只推送 `feat/museum-simulator-mvp`，不合并 main；不提交密钥、个人 Xcode 状态或构建产物。最终五小时末的冻结交付不替代中间提交。

## 7. 用户最终真机自验

本轮不安装或接管用户手机；用户上机后依次确认：

1. 安装本轮构建，核对版本、眼镜连接和权限；真实相机帧增长、原生 HUD 可见。
2. 通过音频路由选眼镜，确认声音确实从眼镜输出；开麦后检查实际输入是否为眼镜，不能由蓝牙连接推定。
3. 一幅画听到总览后自动进入 1 号；讲解中自然发问、改选另一点、暂停后追问、回答后继续；均保持正确点位。
4. 中英各跑一次，检查字幕、倍率与来源；停止／重扫无旧音频。
5. 当前原生构建尚无镜片现实框，记录为缺项。未来 P02 实现后，再单独检查现实框、局部窗、列表与声音是否同点，以及转头／改变距离后的对齐。
6. 连续十分钟，含一次短遮挡和断网／蓝牙变化；记录恢复行为。

现实框绘制与光学映射仍待实现；光学可读性、真实眼镜麦克风、耳边打断时延和端到端延迟保持真机待验。若平台不能满足 P02，向用户给出能力证据与范围选择，不能自行把需求降级。
