## 1. 当前结论

**Web／Simulator MVP 已实现并完成最小服务联调；项目正在进入真实眼镜相机接入阶段。完整的“看向艺术品 → 自动识别 → 语音导览 → 现实细节跟随框”尚未在眼镜上跑通。**

本次新增的两项工作：

1. Web 默认入口改为实时相机优先；收到真实解码帧后才提交识别，内置梵高图片改为用户手动选择的演示入口。眼镜 Web 无相机权限时显示等待／不支持说明，不用预设图片充当实时输入。
2. 准备 iOS DAT 相机接入工程，包括注册、权限、视频帧、后端识别和原生 Display 输出代码。工程尚未完成 Xcode 编译与真机验证。

当前验证结果：**Web 生产构建通过，71 项自动测试通过；iOS Swift 语法和工程配置文件检查通过。**

## 5. 当前阻塞项

### B01：眼镜 Web App 没有相机／麦克风采集权限

本次通过 Meta 官方公共 Wearables 文档服务核实：只有手机端 DAT 能读取眼镜相机或采集麦克风音频。眼镜 Web 支持文本输入、语音转文字输入或可选 WebMCP 工具，不能由此推导拥有原始相机／麦克风流。

因此，把网页默认输入改为视频优先，并不会让它自动读取眼镜摄像头。完整实时输入路线需要 iOS DAT；当前 iOS 工程采用同一 `DeviceSession` 下的相机与原生 Display，不假定独立 Web 页面能与 DAT 显示会话同时占用镜片。

### B02：本机缺少可用 iOS 构建环境

当前 macOS 13.7.5、Swift 5.8.1 与 Command Line Tools 不满足官方 iOS 样例要求。用户表示目前没有另一台可用的构建 Mac，因此只能先准备代码，不能宣称已交付可安装的 iPhone App。

下一步由用户安排系统升级及完整 Xcode 安装；Swift 编译器、iOS SDK 随 Xcode 提供，Meta SDK 从工程依赖解析。此次没有执行 macOS 升级或 Xcode 安装。

### B03：现实跟随框尚无真机验证

相机帧坐标、眼镜显示坐标与人眼视野不自动一致。需要实际显示通路、延迟测量和相机到视野校准；视频画面上的跟踪框不能代替现实艺术品对齐验收。
