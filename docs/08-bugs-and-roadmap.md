## 2. 用户报告的三个问题

### BUG-01：原生语音没有使用 Gemini Live

- 优先级：P0。状态：已定位，未修复。
- 现象：语音听起来像系统机器人女声，与 Web 导览体验不同。
- 代码依据：`TourNarrator` 使用 `AVSpeechSynthesizer` 与系统 `zh-CN`／`en-US` voice；原生 `MuseumBackend` 只连接 HTTP 识别接口，没有连接现有 `/api/live`。
- 根因：0.1.1 为补齐发声引入系统 TTS，尚未迁移 Web 的 Gemini Live 音频链路。视觉与文本仍由 Gemini 处理；音色性别本身不能判断服务来源。
- 修复：接入现有已鉴权的 Live 服务；原生 PCM 播放、字幕分句、播放队列与点位版本一致；中断时丢弃旧音频；沿用 Web voice 配置。系统 TTS 仅作为显式选择的离线方式，不能静默冒充 Gemini。
- 验收：看到 Gemini Live 就绪状态并实际听到云端输出；切点后无旧音频回放；双语、暂停、倍速与输出到眼镜分别实测。
- 关联：P01、P06、P07；A06–A08。

### BUG-02：缺少检测框和持续追踪

- 优先级：P0。状态：已定位，未修复。
- 现象：眼镜上有文字和点位按钮，没有 Web 原型中的细节框。
- 代码依据：`MuseumDetail.box` 已解码，`GlassesDisplay` 没有使用该坐标绘图；相机流中没有本地跨帧追踪。Web 的 OpenCV 追踪没有迁移到原生。
- 修复：维护作品区域、细节区域、原始帧和当前帧之间的变换；二维画作使用平面跟踪，三维展品使用适合视角变化的物体跟踪及重新检测；同步选点、高亮、音频和局部窗；失跟后清除无效框。
- 现实对齐：图像内框与镜片现实跟随框分别验收；仍需要相机到显示／人眼的映射、距离与延迟验证。PRD 未允许把图像内框当作最终 A 版完成。
- 验收：自动讲解与手动选点都持续框住同一现实细节，移动和遮挡后行为正确；记录 A02–A04 实测，不用视频预览代替佩戴验收。
- 关联：P02；A02–A04、A06。

### BUG-03：没有先锁定艺术品，杂物也被讲解

- 优先级：P0。状态：已定位，未修复。
- 现象：场景里有水瓶、包装或线缆时，系统可能围绕这些物品生成讲解；小幅画作容易被忽略。
- 代码依据：收到第 8 帧后对全图发起一次分析；最长边缩到 900 像素；提示词寻找可见细节，契约中缺少作品候选、作品区域和无作品状态。之后依靠手动重扫，没有持续寻找与锁定作品。
- 修复流程：搜索作品候选 → 稳定／确认 → 锁定目标 → 从原始帧裁剪／必要时透视矫正 → 作品内部点位分析 → 讲解与持续追踪。
- 小目标：多尺度／区域搜索、展台与展签上下文、足够的原始分辨率；不能先丢弃细节再靠数字放大恢复。必要时请求更高清帧或提示靠近。
- 边界：不只选最大、最居中的物体；无可靠作品时不自动讲解。日常物品与当代艺术装置可能外观相同，有歧义时参考展陈资料或让用户确认，不能简单永久排除某一物品类别。
- 验收：小画作与杂物共存、多个作品、雕塑／装置、无作品、模糊、遮挡分别测试；同一作品锁定后不随背景行人跳转；信息不足时说明不确定。
- 关联：P01、P05、P06；A01、A11、A12。

## 3. 其余核心功能差距

| ID | 功能 | 当前状态 | 完成标准 |
|---|---|---|---|
| GAP-01 | 自然语音打断与指令 | 原生未实现；按钮操作不等于语音验收 | 接入实际麦克风；起声停止旧音频；编号／名称选点、暂停、继续、下一处、倍率、语言、来源及无效指令澄清；A06、A08 |
| GAP-02 | 多轮追问与恢复 | 原生未实现 | 保留作品与点位上下文；回答后等待继续；恢复当前点，不重播总览、不跳回 1 号、不让旧任务覆盖选择；P06 |
| GAP-03 | 1×／2×／4×局部窗 | Web 有原型，原生未迁移 | 同一基础范围的数字倍率；右上半宽半高、约四分之一面积；切点同步；列表不遮挡窗口；P03–P04、A05 |
| GAP-04 | 作品身份与可靠背景、出处 | 只有一幅梵高样例的已准备资料；原生没有作品库匹配／检索，也未保留和展示完整 sources/sourceIds | 演示作品的身份、作者、年代、背景与逐条资料关联；资料引用和 provenance 分开；未知内容不编造；P08、A09 |
| GAP-05 | 完整中英切换 | 有选择器，当前导览没有原生翻译及状态保留流程 | 切换保留编号、选择、倍率和进度；双语问答、指令、来源全流程；P07、A08 |
| GAP-06 | 跨帧／恢复稳定点位 ID | 同次返回有编号，重扫重新建表 | 同作品在移动、遮挡恢复、重识别和语言切换后保持身份与编号；换作品才建新会话；A11–A12 |
| GAP-07 | 自动导览与定位状态联动 | 系统 TTS 有总览→细节顺序，但未与作品锁定、可见性和定位门槛联动 | 总览完成／跳过后自动进入细节模式；确认可定位后讲 1 号；用户选择优先；列表、声音、框、局部窗一致；P01、P05–P06 |
| GAP-08 | 实际音频倍速与语音调速 | 原生只有系统 TTS 语速档位；不是精确时长倍数 | Gemini 音频 0.75／1／1.25／1.5／1.75／2×；显示同步；语音调速；字幕与音频时间一致；后续会话要求 |
| GAP-09 | 断网、失跟、会话恢复及后台 | 有部分超时与停止处理；进入后台会停止取流和朗读 | 明确连接／重定位状态；保留点位，正确清框与恢复；缓存内容与在线回答分开；明确验证锁屏／后台支持范围；A04、A10 |

## 5. 仍未完成的完整验收

以下是 PRD 拟定目标，尚非已测结果：

- A01：三件登记作品各十次识别，成功率目标至少 90%；陌生作品不能错误确认为库内作品。
- A02–A04：实际镜片现实跟随；稳定段更新目标至少 10 Hz、端到端延迟 p95 不超过 200 ms；静止角点误差 p95 不超过 1°、缓慢移动不超过 2°；失跟后 300 ms 清框目标需实际测量。
- A06–A07：起声到旧音频停止 p95 不超过 500 ms；结束发言到首段回答音频 p95 不超过 3 秒。
- A08–A09：中英文完整流程，背景事实和出处逐项审查。
- A10–A12：十分钟连续导览、短时失跟与断网恢复、稳定编号和点位可靠性。

硬件不在身边时，可以通过 MockDeviceKit 与录像推进功能和回归；镜片可读性、现实坐标对齐、实际蓝牙音频／麦克风和真实延迟仍保留真机待验。

1. 完成 DEV-01 剩余验收：先定位测试进度中三个失败，再补齐未到达断言和手机相机验证；保留可重放素材。
2. 修复 BUG-03，建立作品锁定与可拒绝的分析契约；结合 GAP-04 准备可靠演示资料。
3. 修复 BUG-01，接入双向 Gemini Live，并完成 GAP-01、GAP-02、GAP-08。
4. 修复 BUG-02，加入稳定点位身份、原生追踪与局部窗；图像内与现实对齐分开验收。
5. 完成双语、状态联动、异常恢复、连续运行与现场演示；P0 完成后再安排 3D 范例。
