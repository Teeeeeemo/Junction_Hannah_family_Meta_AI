# MUSE 最终交付与界面收口方案

日期：2026-11-15（Europe/Helsinki）  
基线：iOS 0.2.4 / build 8，源码 `c87da7e`；产品规则以 [PRD](01-product-requirements.md) 为准。  
状态：**最终阶段待实现的代码与 UI 任务。** 最初仅提交本地；2026-11-15 按用户后续要求同步 GitHub，本次不实施应用代码改动。

## 1. 实施阶段与优先级

本方案安排在核心功能修复和验收后的最终收口阶段实施，不能抢占当前 **No.1／P0：P02／BUG-02 跟随检测框修复**。先完成可用的识别、讲解、选点与跟随链路，再执行本文的界面精简、自动连接、入口整理和交付包装。

实施顺序：

1. 修复跟随检测框，分别记录手机视频、模拟 DAT 与实际镜片的结果。
2. 跑通识别作品 → Gemini 概览 → 细节列表 → 自动首点 → 改选／追问的完整流程，补齐稳定性和延迟工作。
3. **最终阶段实现本文的代码与 UI 功能**，执行参观模式与开发调试模式回归。
4. 以最终实际构建录制视频、整理源码与运行材料，按提交平台要求交付。

无实体眼镜期间继续推进可测试部分，镜片对齐和真实音频路由保留待验；不能为赶交付把手机画面内框当作镜片现实跟随已完成。若提交前仍有缺口，按已验证的原型能力展示并准确说明。

本文是最终收口的执行依据，不表示当前 App 已具备下列自动化和布局。细节列表立即展示、三词标题、分段倒计时等规则继续沿用 PRD；倒计时的视觉完善排在框和可靠语音之后，不取消原需求。

## 2. 提交形态

作品名称和叙事围绕 **MUSE 眼镜博物馆导览**。iOS App 是连接眼镜、取流、辅助控制与调试的配套入口，后端提供 Gemini 服务。提交包覆盖可运行体验与工程材料，不以单个 IPA 作为全部交付。

| 材料 | 最终交付内容 |
|---|---|
| 项目介绍 | 参观者问题、眼镜价值、核心流程、Gemini 的实际作用及当前能力边界 |
| 源码 | GitHub 的实际实现分支、可定位的 commit／release、依赖与启动说明；默认分支若未同步须给出正确入口 |
| 操作视频 | 真实构建中的识别、概览、细节选择、提问与跟随效果；说明使用真实眼镜、手机输入还是模拟显示 |
| 现场体验 | 已安装并配置好的手机，眼镜可用时进行实际佩戴体验；手机模式作为可独立运行的演示入口 |
| IPA | 版本、build、源码 commit、SHA-256 和签名安装说明；当前未签名包不能当作评委下载即可直接安装的入口 |
| 运行说明 | iOS／后端配置、权限、连接、音频输出、无眼镜体验和已知限制；密钥留在服务端 |
| 演示链接 | 若提供在线体验，使用适合评审期间访问的部署；不把带临时访问码的本机隧道当作长期公开链接 |

以上是交付建议，具体必填字段、视频时长、文件格式和评奖材料以当届提交表单为准。[Junction 平台介绍](https://hackjunction.app/blogs/how-to-run-a-hackathon-with-junction-platform)介绍项目描述、演示、视频和源码链接，但不能据此推定每个活动的全部要求。

## 3. 手机端参观模式

推荐保留现有 MUSE 金色与深色视觉，减少首页及导览页的调试信息。手机负责准备与辅助操作，眼镜负责观看和主要导览交互。

| 页面／区域 | 最终阶段代码与 UI 要求 |
|---|---|
| 首页 | MUSE 品牌、简短说明、眼镜连接状态、中英切换、醒目的“开始导览”；进入导览后收起大标题，留出作品空间 |
| 开始导览 | 收敛当前分散的后端连接、Meta 注册和相机启动步骤；按已有授权检查并复用连接，必需时引导用户授权。失败给出明确原因与对应动作，不能假装已连接或已启动 |
| 导览页 | 作品名、当前讲解卡片、细节列表、暂停／继续、提问、实际播放倍速和结束导览；开始等待有反馈 |
| 手机画面 | 展示视频及已验证的图像内框，兼顾作品可见性与操作空间；不要在这里声称镜片现实对齐已通过 |
| 次级操作 | 重新识别、来源查看、音频输出选择；异常时仍能快速找到恢复操作 |
| 无眼镜体验 | 独立、易发现的“手机体验”入口，复用导览业务；界面明确标注输入来源，不要求连接实体眼镜 |
| 字幕 | 默认简洁、按完整句显示，可开关；限制行数，长句分屏／分段，避免长文覆盖作品和列表。完整讲解另行展开 |

“开始导览”的自动准备不得绕过系统权限、Meta 授权或用户取消。需要重新配对、权限被拒、无网络或无设备时，保留清晰的失败状态和返回入口。

## 4. 眼镜 Display

| 元素 | 最终呈现要求 |
|---|---|
| 作品与当前段 | 简短作品名、当前点位／概览状态，避免重复堆叠长文字 |
| 细节列表 | 在右侧显示短标题与编号，结果就绪即显示；高亮当前点，可选择和打断，名称、编号与手机一致 |
| 字幕 | 当前句、受限行数、可关闭；完整长文放在手机，不占满镜片 |
| 播放状态 | 简洁展示播放／暂停和当前倍速；每段环形倒计时按 PRD 实现，不能用虚假固定时长替代实际播放进度 |
| 跟随框 | 框住当前细节并随移动更新；可靠定位才显示，切点清旧框，失跟清无效框。镜片映射单独验收 |
| 放大 | 2×／4×局部窗，按 PRD 的右上角布局；可靠定位时启用，失跟清除，不能显示旧细节裁剪图 |
| 控件 | 少量、可读、可命中的播放与选点操作；镜片真实可读性和操作方式需要佩戴验证 |

失跟继续讲解、新点最多等待约 2.5 秒后可开讲的规则保持不变。字幕、列表、点位、框和局部窗共享同一选点状态，旧异步任务不能覆盖新选择。

0.2.4 当前仍未实现眼镜 Display 跟随框；本文没有把该目标标记为完成。

## 5. 开发调试模式

保留工程能力，集中到可主动打开的“开发者设置”。普通参观流程不展示以下内容：

- 输入帧数、Vision 状态、置信度、坐标、识别原始结果与详细日志。
- 后端完整地址、Meta 注册诊断、连接参数。
- 离线布局样例、录像导入和输入源切换的技术选项。
- 大尺寸模拟 DAT 预览和“测试点击处理器”等工程说明。

无眼镜体验本身仍可从普通首页进入；其内部的录像导入、离线布局及诊断工具放在调试模式。离线样例必须保留“非当前画面识别”的标记，模拟 Display 必须保留“模拟”标记，不能因精简 UI 移除这些区别。

错误日志可以折叠，用户需要处理的错误不能被隐藏；诊断输出不得泄露 Gemini Key、访问码或账号凭据。

## 6. 最终阶段任务清单

以下全部为待实现／待验证事项，实际完成后逐项附上构建版本及证据。

- [ ] F01：拆分参观模式与开发调试模式，保留便捷的手机体验入口。
- [ ] F02：将首页收敛为状态、语言与开始导览，导览时收起大尺寸品牌介绍。
- [ ] F03：实现开始导览的连接检查、授权引导与自动准备，覆盖取消及失败重试。
- [ ] F04：精简手机导览卡片与眼镜 Display，限制字幕行数，统一作品名、编号、选点和播放状态。
- [ ] F05：将来源、音频输出和重识别放入合适的次级入口；故障恢复仍能快速到达。
- [ ] F06：将帧数、诊断、录像、样例与模拟预览移入开发者设置，保持模拟／离线标记。
- [ ] F07：回归切点、暂停、倍速、语言、提问、定位恢复与结束，确认 UI 整理没有破坏业务状态。
- [ ] F08：制作与最终版本一致的真实演示视频、截图、运行说明、release 与校验信息。

## 7. 验收与演示

最终收口验收以首次体验者能否操作为准：能够找到开始入口，理解连接或识别等待，对着作品听到讲解，看见列表并选择不同细节，暂停／继续、调速、提问和结束；全程不需要理解 DAT、Vision 或手工处理后端参数。

真实眼镜与手机体验分别走一遍。重点检查字幕遮挡、小屏可读性、按钮命中、语音输出、权限拒绝、后端断开、无作品、切点与恢复。无设备或未联调的项记录为待验，不依据手机预览判定眼镜通过。

推荐演示叙事：面对一幅不熟悉的画 → 识别并听整体 → 列表加载后看到可探索细节 → 选择一个点 → 看到对应跟随效果并听讲解 → 提问 → 返回当前点。自动首点和用户改选至少各展示一次。

若只能使用手机，展示手机输入和模拟眼镜布局，并说明缺少真实佩戴证据。若镜片框尚未完成，明确展示手机图像内框的实际范围；未来产品构想与已运行功能分别描述。

录制后按实际构建更新介绍和材料；不通过剪辑、预置内容或模拟画面掩盖未实现功能。提交动作及新公开部署／上传另按用户指令执行。
