# 开发、测试与交付计划

版本：v0.1 · 2026-11-14（Europe/Helsinki）  
状态：计划与待执行验收表；没有应用测试已通过的含义。  
前提：用户要求先完成文档，再选择手机平台。

## 1. 阶段安排

已完成的工作是产品访谈、PRD、技术设计和平台调研。后续顺序：

1. 用户选择单一主平台，记录真实设备与权限。
2. 运行官方最小示例并完成 Gate 0。
3. 一幅作品端到端实现，然后扩展到建议的三幅。
4. 自动化检查、模拟器验证、真机验收与演示排练。
5. 提供构建产物、源码、操作说明、证据和限制清单。

Codex 负责应用与后端实现、测试设计、可自动执行的检查和交付材料。用户负责提供真实眼镜／手机、完成设备上必须由持有人操作的配对与授权，并反馈佩戴时的实际视觉对齐。测试需要人眼观察时，以真实观察为证据，不从代码推断体验已经通过。

| T14 中英流程 | A08 | 中英各完成概览、选细节、放大、打断、追问、来源和继续；语言切换保留状态 |

## 6. 指标如何测量

### 6.1 现实框

至少记录 3 个观看位置、5 个静止验证点和 3 组缓慢移动。拍摄目标与实际叠加框的可比较证据；能通过镜片拍摄时用相应装置，无法时记录佩戴者逐点对齐判断与测量限制。

角度误差优先使用经确认的显示视场／校准模型换算。无法可靠测角时，应报告显示坐标误差和佩戴者结果，并把 PRD 的角度指标保留为未完成测量；不能假设线性像素缩放便是人眼角度。

### 6.2 延迟与百分位

每个有效样本记录起点、终点和测量时钟。云端不同机器的原始时钟不能直接相减；用户发声到耳边停止可通过同一录音／外部测量比较。端侧起声检测至 stop 调用时间只能作为软件指标。

按升序样本的 nearest-rank 方式报告 p95，并同时记录样本数、场景和失败次数。中英各至少 20 次打断／回答测量；少样本的百分位是初步证据，不是大规模用户统计。

### 6.3 内容审核

整理“讲解句／claim_id → source_id → 网页段落或馆藏字段”的审查表。事实、观察和解释分开核对。测试至少包含一个有争议问题和一个资料不足问题。

## 7. 两分钟演示脚本草案

| 时间 | 用户动作 | 展示的价值 |
|---|---|---|
| 0–20 秒 | 佩戴眼镜对准首幅画 | 识别与简短概览 |
| 20–45 秒 | 系统主动选细节；轻微移动头部 | 现实中的框持续跟随 |
| 45–65 秒 | 用户选择 2×，再选择 4× | 右上角实时局部放大 |
| 65–95 秒 | 直接打断，询问该细节的背景 | 自然中断、上下文问答 |
| 95–110 秒 | 问出处并切换语言 | 可信资料与双语 |
| 110–120 秒 | 继续或结束 | 保持个人节奏与完整闭环 |

脚本不是验收证据。最终演示录屏与旁观者视频应分开标识：实际眼镜显示、手机调试视图、模拟器效果不能混为一谈。
